# ADR-006: Legacy business logic non-reuse – clean-room implementation

**Status:** Accepted
**Date:** 2026-09-03

---

## Context

Az SNI Irányító platform meglévő VédettMunka (`/vedettmunka/*`) funkciói egy eltérő termékkoncepción alapulnak: álláshirdetés, CV-készítés, jelentkezés, munkáltatói regisztráció. Ezek technikai és üzleti struktúrái könnyen "átvehetők" lennének az új Védett Karrierbe, de ez megkötné a termék kezét és lehetetlenné tenné a V2.2.1 FINAL termékkoncepció teljes megvalósítását.

## Decision

A Védett Karrier V2 üzleti logikája **clean-room implementáció**.

Az alábbiak NEM kerülnek reuse-olásra:
- Legacy VédettMunka business taxonomy
- Legacy mezőnevek és kérdésstruktúrák
- Legacy álláshirdetési workflow
- Legacy CV-workflow mint új Karrier alap
- Legacy jelentkezési flow mint új Karrier alap
- Legacy munkáltatói csomag logika
- Legacy munkakörnyezeti mezőlista átnevezése
- Legacy UI information architecture

Az alábbiak reuse-olhatók:
- Generikus Supabase kliens (`lib/supabase/`)
- Auth helpers (session, middleware)
- Shared UI primitívek (Button, Modal, Input)
- Storage infrastruktúra
- Email infrastruktúra (`lib/resend.ts`)
- Generic admin auth utilities
- Logging infrastruktúra
- Accessibility helpers

## Alternatives Considered

- **Meglévő VédettMunka kiterjesztése:** Elutasítva. Strukturálisan inkompatibilis a VKMM typed modellel.
- **Részleges reuse:** Elutasítva. Nehéz határok betartása, nagy regressziós kockázat.

## Consequences

- Lassabb indul az implementáció, de a technikai adósság minimális.
- A két rendszer egymástól függetlenül fejleszthető és karbantartható.
- A clean-room határ dokumentálva van: `CLEAN_ROOM_BOUNDARY.md`.

## Security/Privacy Implications

A clean-room elv csökkenti a véletlen adatszivárgást a két rendszer között.

## Clean-Room Implications

Ez az ADR a clean-room határ elsődleges szabályozója.
