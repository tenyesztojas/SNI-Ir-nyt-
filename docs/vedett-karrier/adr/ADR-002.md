# ADR-002: VKMM typed value model – nincs polymorphic intensity_value text

**Status:** Accepted
**Date:** 2026-09-03

---

## Context

A Védett Karrier Munkakörnyezeti Modell (VKMM) 51 aldimenzióban tárol munkakörnyezeti értékeket. Ezek az értékek eltérő típusúak: ordinális szám, kategorikus szöveg, boolean, frekvencia. Egy polymorphic `intensity_value text` mező minden típust szövegként tárolna, ami validálhatatlan, type-unsafe és bugok forrása (pl. `boolean_value = false` tévesen "üres" értékként értelmezhető).

## Decision

A `job_role_env_values` tábla négy külön typed oszlopot tartalmaz:

```sql
ordinal_value    smallint nullable
categorical_value text    nullable
boolean_value    boolean  nullable   -- false is valid!
frequency_value  text     nullable
```

Pontosan egy oszlop nem-null értékű soronként (CHECK constraint biztosítja).
A `value_type` nem tárolódik a `job_role_env_values` táblában – az aldimenzió lookup-ból elérhető.

## Alternatives Considered

- **Polymorphic `intensity_value text`:** Elutasítva. Nem validálható DB szinten, boolean false elvész, frekvencia index nem lehetséges.
- **JSONB mező:** Elutasítva. Schema-less, index-nehéz, overengineering.
- **Külön típustáblák (HI_values, SM_values stb.):** Elutasítva. Felesleges JOIN komplexitás.

## Consequences

- DB szintű typed validáció lehetséges (trigger).
- TypeScript discriminated union típusok pontosan leképezhetők.
- `boolean_value = false` explicit valid értékként kezelt.
- A seed validator kötelezően ellenőrzi a típus-konzisztenciát.

## Security/Privacy Implications

Nincs közvetlen hatás. A typed model csökkenti a korrupt adat DB-be kerülésének kockázatát.

## Clean-Room Implications

A legacy VédettMunka rendszer (ha volt ilyen mezője) `intensity_value`-ja NEM reuse-olható. Teljes újraírás szükséges.
